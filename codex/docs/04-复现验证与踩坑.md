## 2. 从仓库重新渲染

脚本按 Windows 字体路径配置，使用 Times New Roman、Arial 等本机字体。需先有 FFmpeg、uv 与可用网络；依赖准备好后，渲染过程使用本地素材，不再调用生成 API。

在仓库根目录运行：

```powershell
uv run --python 3.12 --with-requirements codex/tools/requirements.txt codex/tools/render_v4.py all
```

或者双击 [RENDER-v4.cmd](../RENDER-v4.cmd)。生成文件写入忽略追踪的 `codex/build/v4/`，中间文件写到仓库根目录的 `.codex-work/v4/`。

v2 对应：

```powershell
uv run --python 3.12 --with-requirements codex/tools/requirements.txt codex/tools/render_v2.py all
```

也可以运行 `picture` 或 `audio` 阶段；`audio` 依赖已存在的画面拼接结果。第一次先用 `all`。

原始粗剪与 Claude 的 v3、v3.2 文件引用现有仓库的 `assets/05-video/`；Codex 的两个生成结果放在 `codex/assets/source/`。没有把同一批大视频再次复制进 Git 的另一处目录。

完整工程使用 GitHub 根据发布标签自动生成的仓库 ZIP，见 [Release](https://github.com/shangshang21/ai-video-ad-case-study/releases/tag/codex-noctelle-2026-10-22) 下的 **Source code (zip)**。包中含 Claude 主线素材、Codex 新增素材、两版成片与两版渲染脚本；首次解压后仍需准备上述运行环境。分层音轨由脚本的 `audio` 阶段生成。大包上传与归档处理见 [第五篇记录](05-GitHub展示与归档.md)。

## 3. 核查项与证明范围

| 核查 | 实际能确认的内容 | 不能据此声称 |
|---|---|---|
| FFprobe 与帧数 | 格式、时长、分辨率、输出帧数 | 审美合格、源画质被恢复 |
| 全片解码 | 编解码与文件读取未报错 | 每一个动作自然、音乐适合 |
| 联系表与关键连续帧 | 已抽查画面的内容、构图与切点状态 | 真人完整实时观看已经完成 |
| 响度与峰值 | 指定算法测得的综合响度、真峰值 | 真人试听、音乐风格或混音主观验收 |
| 配乐 ASR 空文本 | 未识别出可转写对白或歌词 | 没有任何类似人声的音色 |
| SHA-256 与 ZIP 完整性 | 指定文件与交付记录一致、压缩包成员可读 | 影片在所有播放器都完成了观看验证 |
| 仓库脚本重渲染 | 归档后的路径和依赖能实际产出影片 | 任意系统无依赖就可运行 |

具体执行结果保存在 [validation.json](../manifests/validation.json)。原片和两个成片的文件散列、大小见 [artifacts.json](../manifests/artifacts.json)。

媒体清单对二进制作品与素材记录散列；文本脚本、文档另做语法、链接与内容检查，避免把不同平台的文本换行差异当作媒体损坏。

媒体清单的路径相对 `codex/`，其中 `../assets/05-video/` 指向主线已有的原始粗剪与 Claude 视频。

归档时另外从仓库路径独立重渲染 v4，得到同样的 30 秒和 720 帧。重渲染文件与已交付 MP4 的散列不同；全片逐帧 SSIM 约 0.9916，说明像素接近。这里没有宣称字节级完全复现，SSIM 也不是审美验收。

v2 也从归档后的脚本和路径完整重跑，重新得到 27 秒、648 帧，并通过全片解码检查。两个复现结果分别记录在验证清单中。

## 4. 实际遇到的失败与修正

### Python 命令存在，解释器却不能用

最初命令指向 Windows 商店占位符。用 `uv python list --only-installed` 找到已有 Python，再创建任务虚拟环境，没有把占位符问题误判为电脑不能运行 Python。

### 权限或额度查询不能替代实际任务结果

曾先查询套餐信息，返回结果没有证明视频任务是否能运行。随后同一密钥的 H3 任务实际创建并成功完成。最终以具体服务的请求结果判断能力，没有反复要求用户重新给权限。

### 音乐 API 返回 410

旧音乐接口对本次调用返回不可用。改用 H3 的带声视频生成，再提取音轨，完成了这条素材路线；没有继续循环重试同一个已明确不可用的接口。

### 异步结果与运行时变量

一次查询代码引用了没有保留在可见作用域里的变量，随后从保存的任务结果 JSON 读取任务 ID。一次网络失败也通过查询原任务恢复，避免多创建生成任务。

### ASR 请求中的 FormData 不可用

Node 运行时没有可用的全局 `FormData`，于是改为构造标准 multipart 请求体，完成语音识别检查。这段认证请求没有放进不需要联网生成的渲染工程。

### 私有媒体响应的 Content-Type 判断过严

GitHub 的原始内容响应可能使用带 `json` 字样的媒体类型。最初只凭字符串拒绝了它，后来改为验证 MP4 的 `ftyp` 文件头，并核对媒体大小，再保存结果。

### 浅克隆显示历史不相连

初始只取一层历史，后续再抓一层新提交时，Git 暂时缺少中间祖先，普通快进合并报历史不相连。补取两层历史后正常快进；没有重置工作区、允许无关历史合并或强推。

### 一遍响度处理没有精确达到目标

第一遍输出与目标存在差别，因此改为先测量再处理，并重新测量最终 AAC。最后记录实测值，保留 PCM 与压缩音频峰值存在少量差别的事实。

### 预览图已经存在

一次重导出时 FFmpeg 拒绝覆盖旧预览图。随后只对本轮生成的预览输出加 `-y` 重导出；原始素材仍保留。
